# 保留本机凭据的发布流程

用户要求本机保留私有身份。不要删除、移动、覆盖 `~/.proloader` 或 `cache`，不要为发布执行破坏性clean/reset，也不要先把整个工作目录git add再清理。

## 独立发布目录

用户指定的大型建筑测试通过后，运行：

```sh
python3 .agents/skills/proloader-maintenance/scripts/export_release.py \
  --source /path/to/proloader --destination /path/outside/project/proloader-release
```

目标目录必须不存在且位于源目录以外。脚本按允许列表复制源码、测试、许可和公开维护skill；不复制本机cache、bots、日志、历史交接、个人AGENTS、用户建筑或已构建二进制。它只读本机身份中的会话/token字段，用于扫描待发布内容是否误含当前凭据；只输出文件路径，不输出凭据值。导出后再次核对本机私有文件未变。

允许列表和当前凭据扫描不是完整安全证明。还需检查源代码、历史示例、上游样本、发布README及新增文件是否含硬编码秘密/个人信息；加密或压缩材料需要单独检查。若脚本排除了新的必要构建资源，应审查后扩充允许列表，不得为了构建方便打包cache。

## 发布前核对

- 从干净目录构建并跑测试。`go.mod`/`go.sum`、原生助手及所有必需embed资产完整；不能仅依赖开发机的二进制或外部cache。
- 本项目当前按源码checkout运行；若准备wheel/单文件分发，应先解决third_party原生资源定位与打包，不能假称普通wheel已可运行。
- 更新版本号、安装说明、已验收协议/版本、变更记录与真实能力边界。NBT源码包含不等于NBT功能可用；64点名称抽样不等于完整NBT/states验证。
- 保留AGPL-3.0、原MIT、各子模块许可及对应源码/修改/依赖锁。核实二次分发的传递依赖义务，不能假定进程隔离可以规避许可。
- `third_party/fatalder-source.json`保持可复现来源；未知commit应标未知，不能捏造。
- 本机测试凭据、服务编号、手机号、昵称、绝对用户路径、抓包和私有诊断不进入公开内容。公开repo的AGENTS可以从维护入口重新编写，不复制本机个人记忆。
- 用户确认大型测试通过后才能准备实际发布；推送/建仓库/发布Release按当时授权范围执行。上传前展示明确的仓库目标与待发布内容。
